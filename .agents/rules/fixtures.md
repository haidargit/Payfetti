# Fixtures

`fixtures/*.json` are committed on purpose. The README sends reviewers to
`scripts/verify-run.py --proofs fixtures/…`, and without the proofs that command
fails, so every "paid and proven" figure in the README becomes an unverifiable
claim. They also cannot be regenerated by a reader: `scripts/build-batch.py` is
withheld from git.

So the fixtures are evidence, and they have to stay public.

## What makes that safe today

Nothing in a committed fixture is private, and that is not an accident:

| Field | Why publishing it costs nothing |
|---|---|
| `payer` | the payer signed the transaction; the address is already on-chain |
| `payfetti`, `runId`, `root`, `noteHash` | all four are in the public `RunRecorded` event |
| `amount`, `note` | already on-chain when the run used `--memo-notes` |
| `leaf`, `proof` | recomputable by anyone from the fields above |
| `payee` | **generated, not collected** — see below |

Demo payees come from `derive_payees()`: `keccak256(runLabel ‖ index)`, last 20
bytes. No private key exists for them. The testnet cents sent there are
unspendable forever, which is the point: it keeps the demo honest instead of
paying our own wallet in a loop.

Confirm it for any fixture:

```python
keccak256(b"<runLabel>" + enc_uint(i))[-20:]   # == rows[i]["payee"]
```

## The rule

**Never commit a fixture built from a real run.**

A fixture from a mainnet payout would publish actual recipients' wallet
addresses, what each person was paid, and a note saying why — permanently, in a
public repo, with no way to retract. That is a privacy leak about third parties
who never agreed to it, and it is far worse than the on-chain exposure those
people already accepted, because a git repo collates it into one searchable file.

Before committing anything under `fixtures/`:

- [ ] `network` is `testnet`
- [ ] every `payee` re-derives from `keccak256(runLabel ‖ index)`
- [ ] no `note` contains a real person's name or identifier

If a real run needs to be verifiable by someone else, hand them the exported run
file directly. It is the same data; it just does not belong in git.
