# Honest limits

## Payees need a wallet address

This is the real ceiling on reach, and v1 does not solve it. Email claim links,
passkey wallets and local cash-out are phase two, not something hiding behind a
flag today.

## The payer must be an EOA

`CallFrom` accepts only its allowlisted predeploys, so a Safe or an ERC-4337
smart account **cannot pay through Payfetti at all**. That is a protocol
constraint rather than something a later version patches, and it rules out
multisig treasuries. Measured, not inferred.

## Your past runs cannot be listed

Arc's public RPC refuses wide `getLogs` ranges, so there is no way to enumerate
the runs an address has made. The chain proves any run you can name; it will not
tell you which ones were yours.

This is why exporting the run file is part of the flow rather than a
convenience. Lose it and the payment is still final and still real, but your
payees lose the proofs.

## An on-chain note is public forever

We neither screen nor redact what a payer types. Turn notes off for anything
identifying.

## No fee, no screening

v1 charges nothing and performs no compliance screening. Arc enforces USDC
blocklists at the protocol level, so a transfer to a screened address simply
reverts and shows up as a skipped payee.

## A receipt is not a contract

It proves a payment was committed to and made. It does not prove the amount was
fair, owed, or agreed, and it does not prove the payer's identity beyond their
address.

## This does not create work

Payfetti makes paying for work that already exists possible, which is one layer
below a marketplace. If nobody wants to pay 200 people $1, this changes nothing.

## Still outstanding

- An end-to-end run at full scale on mainnet. The largest executed so far is 50
  payees on testnet; mainnet runs to date have been small.

Payfetti is deployed on Arc mainnet and on Arc testnet, at the same address, with
byte-identical code. Its source is verified on both explorers, so the readable
Solidity there is provably the bytecode actually running.

The explorer grades that verification a **partial match**. The build strips the
metadata trailer solc normally appends, which is what a full match compares
against, so partial is the ceiling for this bytecode. The code is confirmed; only
the compiler's paperwork is not re-derivable. The repository README explains the
trade in full.
